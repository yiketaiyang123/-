## 1. 目标与非目标

**目标**

1. 首次进入聊天时，一次性扫描角色卡绑定世界书 + 手动追加世界书，给每条生成**分类元数据**。
2. 运行时各任务只取自己需要的 `kind`，**正文直接读原书，不二次改写**。
3. 支持人工复核、永久屏蔽、增量重扫。
4. 给每个任务配"标签白名单 + 预算"，不把切死。

**非目标**

- 不做世界书摘要压缩（正文即真源）；
- 不改写原文；
- 不做"每轮让模型从目录里挑条目"；
- 不引入 ST-Prompt-Template / EJS 依赖。

## 2. 数据源

- 角色卡：`getContext().characters[characterId]`
- 绑定世界书：`char.data.extensions.world`（否则内嵌 `char.data.character_book.entries`）
- 手动追加：`store.manual_worldbooks[]`
- 读取：`ctx.loadWorldInfo(name)` → `data.entries`（uid → { comment, key, keysecondary, content, disable, constant, order, position, probability, selective, ... }）
- 读取失败单本忽略、整批标记 `partial`，不阻塞聊天。

## 3. 流程

```text
首次进入 / 手动重扫
1. 读取与快照        记录每条的 sourceHash
2. 粗筛（本地）      零模型调用
3. 预扫描归类        脚本/纯格式条目直接定 kind，不送模型
4. 精筛（模型）      按字符预算分批，失败二分重发
5. 校验              数量/ID/枚举/长度/不改写原文
6. 人工复核          面板：分类、important、blocked、intro 可改
7. 落库              worldbook_catalog + worldbook_meta
8. 增量重扫          只重扫变化条目
```

## 4. 粗筛规则（本地，零成本）

| 条件 | 处理 |
|---|---|
| `disable === true` | `deferred`：启用后再扫 |
| 内容为空 / 极短（< 20 字且无 key） | 剔除 |
| 纯脚本/占位符（> 80% 为 `{{}}`、`<% %>`、`@@`） | `kind = 文风格式`，`blocked = true` |
| 完全重复（正文 + key 哈希相同） | 保留第一条，其余 `blocked` 指向重复 |
| 用户黑名单 | `blocked = true` |
| 其余 | 进精筛 |

## 5. 分类契约（精筛输出）

每条输出：

| 字段 | 类型 | 约束 |
|---|---|---|
| `kind` | 枚举 | 世界基础 / 规则禁忌 / 力量体系 / 地理 / 势力 / NPC / 物品资源 / 事件 / 文风格式 / 其它（兜底） |
| `intro` | string | ≤ 60 字，一句话简介 |
| `retrieveWhen` | string | ≤ 80 字，何时该取 |
| `important` | bool | 建议保留；`constant` 条目自动为 true |
| `needsReview` | bool | 拿不准时 true |
| `blocked` | bool | 仅粗筛/人工设置，模型不得新增屏蔽 |

校验：返回条目数 = 输入条目数、id 不重不漏、`kind` 在枚举内、`intro`/`retrieveWhen` 长度合规。

## 6. 每任务分配（默认值，面板可改）

| 任务 | 默认 kind 白名单 |
|---|---|
| T2 规则引擎 | 规则禁忌、力量体系、世界基础 |
| T3 任务链 | 势力、NPC、物品资源、地理、规则禁忌 |
| T4 地图 | 地理、势力、事件、规则禁忌 |
| T5 命运事件 | 事件、地理、势力（伏笔等动态数据另算） |

存储键：`settings.task_entry_whitelist[taskId]`、`settings.task_entry_budget[taskId] = { maxEntries, maxChars }`。

## 7. 运行时取用规则

- `selection = catalog(kind ∈ whitelist 且 !blocked) + 手动强制加入`
- 预算：默认 `maxEntries = 16`、`maxChars = 24000`（每任务可调）
- 裁剪顺序：`important` > 本轮关键词命中（可选，默认关） > 最近变更 > 其余
- 被裁条目写日志 + 面板可见，不静默丢弃。

## 8. 变更检测（增量重扫）

- `sourceHash = sha256(book + uid + content + key + keysecondary + order)`（排除 `displayIndex`、`disable`、`constant` 这类运行开关）
- 变化条目只重扫该条；新增追加；删除移除；
- 禁用 → `deferred`；启用 → 重新进精筛。

## 9. 失败与降级

| 情况 | 处理 |
|---|---|
| 世界书读取失败 | 用角色卡文本兜底，标 `partial` |
| 精筛调用失败 | 二分重发，预算 16 次；仍失败 → 该批 `needsReview = true`、不阻塞 |
| 整体分类失败 | 进入 `degraded` 模式：运行时按预算裁剪全部未 blocked 条目，不按 kind 过滤，并在面板提示 |
| 分类结果缺条目 | 缺失条目 `needsReview = true`，保留原文可用 |

## 10. 数据存储

```text
store.worldbook_catalog = { [book]: { [uid]: { kind, intro, retrieveWhen, important, needsReview, blocked, sourceHash } } }
store.worldbook_meta    = { scannedAt, sourceHashByBook, status: full|partial|degraded, pendingDeferred[] }
```

## 11. 验收标准

**离线（夹具，不调模型）**

- 粗筛：禁用/空/重复/脚本/黑名单六种输入各得预期结果；
- 预算裁剪：给定 30 条、上限 16 条，按优先级裁到 16 且日志正确；
- 校验器：数量不符、重复 id、非法 kind、超长字段各拒绝一次。

**真机（必须，未完成前不算交付）**

- 真实角色卡扫描后，面板显示条目总数、保留/屏蔽数、预计 token；
- T2 日志里只出现规则类条目；
- 改一条世界书 → 重扫只报该条变化；
- 手动屏蔽一条 → 运行时不再出现；
- 超预算时裁剪日志可见。

**不做为验收项**：分类准确率的主观评分（靠复核面板兜底）。

## 12. 实施里程碑

| 里程碑 | 内容 | 退出条件 |
|---|---|---|
| M1 | 读取 + 粗筛 + catalog 存储 | 夹具通过，面板能列出条目 |
| M2 | 精筛 + 校验 + 二分重发 | 模拟拒绝场景能二分并收敛 |
| M3 | 复核 UI（分类/important/blocked/预算估算） | 改动落库且刷新可见 |
| M4 | 每任务白名单 + 预算裁剪 + 日志 | 夹具断言裁剪顺序 |
| M5 | 增量重扫 + 离线测试 + 真机验收 | 真机四项验收通过 |

## 13. 风险与未验证

1. 真实世界书条目结构差异（uid 类型、key 形态、`disable` 位置）——必须真机验证；
2. 分类误判——`needsReview` + 人工复核 + 一键全保留；
3. 大书扫描成本——批大小与二分预算；
4. 目标 ST 版本未确认——API 形状需按实际版本核对。

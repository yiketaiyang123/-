# T2 · 行动选项与检定 蓝图 v2.0

- 状态：已定稿（2026-11-02）
- 上游：[00-执行逻辑与五任务基础说明-v0.1](00-执行逻辑与五任务基础说明-v0.1.md)、[01-T1-世界模型.md](01-T1-世界模型.md)
- 说明：本版**取代** v1 的"合规判断 / 背景资料 / 世界反馈"，T2 改为**生成后**运行的行动选项生成器 + 检定执行器。

## 1. 目标与非目标

**目标**

1. 主 AI 回复后，读最新剧情生成 **5 条行动选项**（含成功/失败结果）。
2. 选项渲染到该条 AI 回复底部，玩家可见文本，成功/失败隐藏。
3. 玩家点选后，插件本地掷骰判定，**只把命中的分支**连同元叙事发给主 AI。
4. 属性独立成表，由背景首次生成，只在大成功/大失败时成长。

**非目标**

- 不做合规判断、背景资料补充、世界反馈（v1 已删除）；
- 不做对抗检定、不做特殊属性、不引入"绝对成功"档；
- 不生成数值运算或既定结果（不得写"击杀""砍头"）；
- 不触发 T3/T4；任务链/地图的推进维护不在本任务（见第 12 节）。

## 2. 时机

```text
主 AI 回复完成（GENERATION_ENDED）
 └─ T2 异步生成 5 条选项
      → 追加到该条回复底部（可见选项 + 隐藏分支）
玩家点选
 └─ 插件掷骰（本地，无 LLM）
      → 拼元叙事 + 命中分支
      → 自动发送 / 只填入输入框
主 AI 生成下一轮
```

生成前不再有 LLM 调用，只剩文本拼装，解决"玩家输入时等待太久"。

## 3. 属性系统

固定 8 项，数值 1–100，独立于角色卡数值：

```text
力量 敏捷 体质 感知 智力 意志 魅力 幸运
```

- **首次进入**扫描用户角色背景（persona/描述）生成初始值，推荐区间 30–75，按背景给强弱项；
- **成长**：对应属性大成功/大失败时 +1，上限 99，写入成长记录；
- 只对 `<user>` 生效；面板可重生成、可手改。

## 4. 难度（四档，AI 生成选项时确定）

| 难度 | 目标值 | 执行 |
|---|---|---|
| 常规 | 属性值 | 掷 1d100 |
| 困难 | ⌊属性/2⌋ | 掷 1d100 |
| 极难 | ⌊属性/5⌋ | 掷 1d100 |
| **绝对失败** | 无 | **不掷骰，直接判失败** |

- 难度由 AI 按局面给：玩家 1 级对 99 级目标 → 绝对失败；
- 混合属性（如 幸运+魅力）：取平均向下取整；
- 奖励/惩罚骰：多掷一颗十位骰，奖励取低、惩罚取高。

## 5. 检定执行与元叙事

- 掷 1d100，`≤ 目标值` 成功；
- 成功等级内部按 CoC 判（用于成长）：大成功 ≤5；极难 ≤⌊属性/5⌋；困难 ≤⌊属性/2⌋；普通 ≤属性；大失败：属性<50 时 ≥96，属性≥50 时 =100；
- 对外只显示 **成功 / 失败**；
- 元叙事格式：

```text
常规：发起了【感知】检定，1d100=39，判定 39 <= 52？成立，判定为【成功】
绝对失败：难度：绝对失败，判定为【失败】
```

- 发送内容 = 行动描述 + 元叙事 + 命中分支（成功或失败）。

## 6. T2 输出契约

一次生成 5 条：

```json
{
  "选项": [
    {
      "类型": "洞察",
      "属性": ["感知"],
      "难度": "常规",
      "奖惩": null,
      "描述": "林言走在队伍中，仔细聆听荒废酒庄一楼大厅的动静，判断是否还有隐藏的邪教同伙或魔物。",
      "成功": "检定成功了，林言提前发现潜藏的威胁，做好防备。",
      "失败": "检定失败了，林言被突发的偷袭打个措手不及，队伍陷入短暂混乱。"
    }
  ]
}
```

约束：正好 5 条；`属性` 必须是 8 项之一（可混合）；`难度` ∈ 四档；描述/成功/失败各 ≤ 80 字。

## 7. 生成约束（写进提示词）

**禁止**

- 数值运算：伤害值、成功率、等级差换算；
- 既定结果："击杀目标""砍下对方的头""一剑毙命""必然被擒"；
- 替 NPC 决定反应。

**只允许**

- 行动意图与方式："向目标发动偷袭""绕到侧翼""用话术套取消息"；
- 结果只写进隐藏的【成功】/【失败】段，且是行动后果，不是"你赢了"。

## 8. 渲染与交互

- 可见：`【类型】` +（难度开关开启时）`【常规/困难/极难/绝对失败】` + 描述；
- 隐藏：`【成功】…【失败】…`，玩家不可见，只存在于消息文本里；
- 隐藏块附带任务链节点与地图内容（由插件从 store 拼，不进 T2 生成）；
- 点击模式：`直接发送` / `只填入输入框`；
- 难度显示：全局开关。

## 9. 点击后的处理

1. 解析被点选项，取属性/难度/成功/失败；
2. 绝对失败 → 不掷骰，直接失败；
3. 否则掷骰、算目标、判成败；
4. 生成元叙事；
5. 拼"行动描述 + 元叙事 + 命中分支"；
6. 按模式发送或填入输入框；
7. 从原消息中移除未命中的分支（避免主 AI 看到没发生的版本），并移除选项块防重复点击。

## 10. 校验与失败降级

| 情况 | 处理 |
|---|---|
| 选项数 ≠ 5 / 字段缺失 | 重试一次；仍失败 → 本轮不出选项，记日志 |
| 属性不在 8 项内 | 该条剔除 |
| 难度非法 | 该条剔除 |
| 描述/结果超长 | 截断并记日志 |
| T2 整体失败 | 不追加选项，主 AI 回复照常 |

## 11. 验收标准

**离线**

- 目标值计算（常规/困难/极难/绝对失败）四组断言；
- 大成功/大失败阈值与成长 +1 断言；
- 元叙事字符串格式断言（含绝对失败无骰）；
- 点击只发送命中分支的断言。

**真机（必须）**

- 选项出现在 AI 回复底部，难度开关可切；
- 成功/失败文本玩家看不到；
- 点选后自动发送/填入两种模式都可用；
- 主 AI 下一轮只看到命中分支，看不到另一条。

## 12. 与 T3/T4 的边界（待后续规格）

v1 里 T2 承担的"任务链/地图维护"在本版移除。**任务链推进、地图探索更新由谁负责，留到 T3/T4 规格里定**；本任务只负责把他们的节点/地图内容拼进隐藏块展示。

## 13. 里程碑

| 里程碑 | 内容 | 退出条件 |
|---|---|---|
| M1 | 属性生成 + 存储 | 夹具生成 8 项且可改 |
| M2 | 选项生成 + 校验 | 5 条结构合规 |
| M3 | 渲染 + 点击 + 掷骰 + 元叙事 | 离线断言通过 |
| M4 | 真机验收 | 四项真机通过 |

## 14. 风险与未验证

1. 消息内可点击选项的渲染/事件绑定需真机验证（你已判断可行，我仍标为门）；
2. 属性生成质量依赖背景文本；
3. 混合属性平均法可能与你的预期不同；
4. 大成功/大失败只影响成长、不影响分支文本，可能与"成功/失败两段"的粒度冲突，后续可加"大成功文本"。

## 15. v2.1 兼容扩展（T3/T4 适配）

T3/T4 不再靠 2A 信号，改由 T2 每次生成顺带返回状态，插件校验后落库；开关关闭时对应字段可缺省。

```json
{
  "场景": { "类型": "开放 | 封闭", "名称": "", "是否变化": false },
  "任务链更新": {
    "状态": "无任务 | 活跃中 | 已完成",
    "当前节点": 2,
    "节点结果": "",
    "结局": "表 | 真 | 失败",
    "即时后果": ""
  },
  "地图更新": {
    "当前位置": "",
    "已探索": ["①"],
    "区域状态": [ { "编号": "①", "状态": "已清除" } ]
  }
}
```

校验：节点序号必须存在于任务链事件链；区域编号必须存在于地图；已探索只增不减；时限与冷却由插件按游戏日扣，不采信 AI 自报。该扩展让 T2 一次调用同时完成“出选项 + 维护 T3/T4 状态”，不新增 LLM 调用。

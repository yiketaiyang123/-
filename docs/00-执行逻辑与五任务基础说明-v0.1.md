# 插件执行逻辑与五任务基础说明（理解稿 v0.1）

- 日期：2026-10-30
- 状态：理解稿，待逐条批注；不是最终总设计案
- 适用版本：Ananke 重制版（旧版 v1.10.7 为重构来源）
- 说明：本稿只描述"新架构下怎么跑"，不涉及代码实现与最终验收

## 一、总执行流程

```text
启动（APP_READY）
 └─ 加载设置 / 安装前置拦截 / 注入面板入口

首次进入聊天（store.world_model 为空）
 └─ 读取角色卡 + 世界书 → T1 世界模型 → 写入 store
      失败：降级基础模型并标记「待补」，不阻塞对话

每轮用户提交（生成前拦截）
 ├─ 捕获本轮输入（chat 最后用户消息 → 输入框 → params.prompt）
 ├─ 轮次+1、冷却递减
 ├─ 插件掷骰（决定本轮世界要不要动）
 │    ├─ 任务链：无链 && 冷却=0 && rng<p_chain → 登记 2B
 │    ├─ 地图：  封闭场景 && 无图/需新图 && rng<p_map → 登记 2C
 │    └─ 命运：  冷却=0 && rng<p_fate → 从事件库抽一条事件
 ├─ T2 规则引擎（每轮）→ 状态增量 + <supplement>
 ├─ 若命运抽中 → T5 命运事件 → <fate_inject>
 ├─ 合并注入 → 写回 prompt
 └─ 主 AI 生成

主 AI 回复完成
 ├─ 消费队列（都吃本轮正文作衔接）
 │    ├─ 2B → T3 任务链 → 写 store.task_chain
 │    └─ 2C → T4 地图（含概率事件表）→ 写 store.map
 ├─ 保存快照（本轮完整状态）
 └─ 刷新面板

删楼 / 切换聊天
 └─ 快照恢复 + 清空队列
```

三条铁律：

1. 只有"用户提交 → 主 AI 生成"这一个交互入口；
2. 2B/2C 永远在本轮正文之后；
3. 除 T2（每轮）和 T5（抽中时）外，生成都不阻塞主 AI。

## 二、五任务总表

| 任务 | 触发 | 读什么 | 输出 | 写入 | 注入主 AI | 失败 |
|---|---|---|---|---|---|---|
| **T1 世界模型** | 首次进入自动 / 手动重跑 | 角色卡、绑定世界书、手动世界书 | `<store>` 世界模型 JSON | `world_model` | 否 | 降级基础模型，标待补 |
| **T2 规则引擎（2A）** | 每轮（可降频） | 规则模型、用户输入、历史、任务链/地图/时钟 | `<store>` 判定+增量，`<supplement>` | `rules_check`、状态字段 | 是 | 跳过本轮注入，主 AI 照常跑 |
| **T3 任务链（2B）** | 插件掷骰命中 | 种子卡、本轮正文、世界模型、阶段、玩家状态 | `<store>` 任务链 JSON | `task_chain` | 否（下轮 T2 读） | 标记 failed，可重试 |
| **T4 地图（2C）** | 进入封闭场景 + 掷骰 | 场景描述、世界模型地理、阶段/等级、本轮正文 | `<store>` 地图 + 区域概率事件表 | `map` | 否（下轮 T2 读） | 重试，保留旧图 |
| **T5 命运事件（3）** | 插件掷骰命中 | 抽中事件、当前区域/状态、最近命运、本轮输入 | `<store>` 事件记录，`<fate_inject>` | `fate_history` | 是 | 跳过本轮命运 |

## 三、逐任务基础说明

### T1 世界模型

- **数据来源（旧代码已可用）**：角色卡 `characters[characterId]`（name/description/personality/scenario）；绑定世界书 `char.data.extensions.world` → `ctx.loadWorldInfo(name)` 取 `entries`（comment/key/content/disable）；读不到再用内嵌 `character_book.entries` 兜底；再合并面板手动追加的世界书；外加 `powerUserSettings` 的 persona。
- **预处理**：跳过 disabled、按 `标题+内容` 去重、剔除 thought/img 标签、超长按条目预算截断。
- **输出**（`<store>` JSON）：
  `world_model = { 基础{名/纪元/类型/法则/历法}, 力量体系{主体系[等级阶梯+突破条件+限制], 副体系[]}, 规则与禁忌[{id, 规则, 类型:硬|软, 例外, 违约后果}], 地理{区域[{id, 名, 类型, 危险度, 相邻}]}, 势力[{名, 目标, 资源, 冲突}], 资源经济{货币/稀有物/获取} }`
- **写入**：`store.world_model` + `world_model_meta{来源哈希, 版本, 生成时间, 状态}`。
- **待定**：世界书可能几万 token，全量喂还是"先过滤相关条目 + 分批提取再合并"。

### T2 规则引擎（2A）

- **输入**：`world_model` 的规则子集（硬规则全量 + 按场景检索的软规则）、当前阶段/等级、本轮用户输入、最近 N 楼（含主 AI 正文）、当前任务链、地图当前位置、时钟、伏笔、本轮抽中的命运事件。
- **输出**：
  - `<store>`：`{ 合规判定{结果:合规|擦边|违规, 依据规则:[id], 风险:低|中|高}, 反馈建议, 影响建议, 状态增量{clock?, 玩家状态?, 地图进度?, 伏笔?, 时间线?, 阶段?} }`
  - `<supplement>`：演出指导（规则引用 + 世界反应 + 影响建议）。
- **注入**：`supplement` 进主 AI；合规判定的详细结果只落库给面板看。
- **待定**：阶段从 `world_model.成长阶梯` + 玩家等级映射（倾向方案）；2A 是否每轮必跑（成本 vs 一致性）。

### T3 任务链（2B）

- **触发**：无活跃链 + 冷却归零 + 掷骰命中。**种子由插件选**（地图区域 / 势力 / 伏笔 / 阶段事件），不再靠 2A 发信号。
- **输入**：种子卡（插件拼的轻量引子）、本轮正文、世界模型、当前阶段、玩家状态、历史任务记录（防重复）。
- **输出**（`<store>`）：`task_chain = { id(插件分配), 名称, 状态, 任务时限, 阶段归属, 任务梗概{表面故事/真实原委/关键NPC/核心矛盾}, 事件链[], 结局[] }`，结构沿用旧版精简，去掉 `#TMP001` 写死编号。
- **写入**：`task_chain`；不注入，下一轮 T2 读。

### T4 地图（2C）

- **触发**：进入封闭场景 + 掷骰（或条件触发，比例可调）。
- **输入**：场景描述（位置/概述/氛围/设施）、`world_model.地理`、当前阶段/等级（敌对上限）、本轮正文。
- **输出**（`<store>`）：`map = { 地点名, 结构, 入口/出口, 当前位置, 区域[]{ id, 名, 状态, 用途, 描述, 连接, 敌对[], 元素[], 概率事件[] }, 敌对总览[] }`
  - `概率事件 = { id, 名称, 类型:遭遇|魔物|机遇|危险|剧情, 权重, 触发条件, 结果提示 }`
- **写入**：`map` + `scene_type=closed`；不注入。

### T5 命运事件（3）

- **触发**：每轮（或每 N 轮）+ 概率 + 冷却；**插件先加权抽取**（权重 = 基础权重 × 地点危险度 × 阶段系数 × 冷却衰减），AI 只负责把抽中的事件写成"安排 + 后果"。
- **输入**：抽中事件、当前区域/玩家状态、最近命运记录（防重复）、本轮用户输入。
- **输出**：`<store>` 事件记录（事件 id/类型/强度/因果）+ `<fate_inject>`（事件安排 + 后果，不写 NPC 台词）。
- **注入**：`fate_inject` 进主 AI。
- **待定**：T5 用 LLM 扩写（贴合本轮）还是插件直接拼 `结果提示`（零调用、可复现）——首版倾向 LLM 轻量扩写。

## 四、调度关系

```text
T1 ──(世界模型)──┬──> T2（规则依据）
                 ├──> T3（地理/势力/规则）
                 └──> T4（地理/危险度）

T3 ──(伏笔/结局)──> 事件库
T4 ──(概率事件)───> 事件库 ──> T5

T2 ──(状态增量)──> 下一轮 T2/T3/T4/T5
```

- **串行**：T2 → T5（抽中时）→ 注入；T3/T4 回复后逐条串行（间隔 1 秒，沿用旧版）。
- **并行**：首版不做并行（旧版也没有真正的 order 调度）。
- **冷却**：任务链完成写 `N 游戏日` 冷却（随游戏日递减，插件权威）；地图按场景存在性；命运按轮次+概率。

## 五、每轮注入构成

```text
final_directive（含 <本轮用户输入>）
  + <supplement>（T2）
  + <fate_inject>（T5，抽中时）
```

2B/2C **不注入**，只落库。注入要加长度预算（旧版没有，是债）。

## 六、数据字典（store v2 关键字段）

`world_model`、`rules_check`（最近一次判定）、`task_chain`、`map`（含区域事件表）、`event_library`（派生）、`scheduler_state{概率参数, 冷却, rng 种子, 队列}`、`clock`、`player_status`、`foreshadowing`、`timeline_events`、`task_history`、`fate_history`。

## 七、仍需定的五个点

1. T1 世界书：全量喂，还是先过滤相关条目 + 分批提取？
2. 2A 频率：每轮必跑，还是允许降频？
3. 阶段来源：从世界模型成长阶梯 + 玩家等级映射（推荐），还是保留独立的阶段规划？
4. 2C 触发：进入封闭场景即触发（条件），还是也要概率？
5. T5：LLM 轻量扩写（推荐），还是插件直接拼结果？
